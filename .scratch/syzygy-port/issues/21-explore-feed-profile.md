# 21: Explore, Feed and Profile Pages

**What to build:** the user can browse Explore and its sub-pages, see new releases from artists they follow on the Feed (with an unseen badge in the sidebar), and view a read-only Profile with its playlists. See user stories 51–53.

**Blocked by:** 17

**Status:** ready-for-agent

- [x] Explore and ExplorePage (sub-pages for genres, moods and editorial content)
- [x] Feed lists new releases. Opening it calls mark-seen
- [x] The sidebar's unseen badge comes from one feed check after login and clears after mark-seen
- [x] A read-only Profile Page and a ProfilePlaylists Page, for the user's own profile or another user's public one

## Comments

Implemented. Notes for later tickets:

- **Catalog.** New modules `explore`, `feed` and `profile`. `Catalog::explore(path)` reads an Explore Page through `TidalClient::get_page` (SWR, Dynamic tier, key `section:{path}`, tag `section`, encoded like Home so an empty page is never cached). `explore::ROOT` is `pages/explore`. An `ExplorePage` is `Section::Links { title, view_all, links }` (sone's `isNavLinkSection`; links with no path or title are dropped) or `Section::Cards { title, view_all, cards }` (cards from `home_feed::cards`, and `view_all` only when TIDAL says there's more). `Catalog::feed(user)` / `mark_feed_seen(user)`: **the Feed is not cached**, unlike sone's 15-minute TTL. sone documents a race where a cached body keeps a nonzero unseen count after mark-seen, and that would bring the dot back on the next launch. `Feed { entries, unseen }`. An entry is a `Card` (releases read "Single by Ado, KUROMI"; mixes lead to the mix; an unknown kind leads nowhere) plus its `Month`. `Feed::grouped(Month::now())` is sone's `groupFeedByPeriod`: calendar months in UTC, so no date crate is needed. `Catalog::profile(user)` is SWR in the UserContent tier, key `profile:{id}`, tags `profile` and `profile:{id}`. `Profile { name, handle, bio, fans, picture, playlists }`: `facts()` gives "@ada · 1.3K fans", `called()` is the name, else the handle, else "Profile". The picture is the smallest square that is sharp at 2x, and the playlists are cards. `Playlist::profile()` is the creator's user id, but only for `type: USER` playlists (`Creator.user`). Artists' and TIDAL's playlists have creators with no user profile: they 404.
- **Routes and Pages.** `Explore`, `ExplorePage { path, title }`, `Feed`, `Profile { user_id }`, `ProfilePlaylists { user_id }`. One `page::explore` module serves Explore and the Pages under it. Explore shows titled link sections as pills (with View all), then the untitled ones as icon shortcuts (sone's `ICON_MAP`). A Page of nothing but links ("All Genres") is one list. A card section's View all opens an `ExplorePage` on its path, and a lone untitled card section shows as a grid. Pills wrap instead of scrolling sideways. The Feed Page groups rows by month. Profile is a hero (round picture or a person placeholder), the bio, and a "Public playlists" card row with View all. ProfilePlaylists reads the same profile. `Load::Profile { user_id, then }` follows `Load::Artist`. `page::no_picture` and `style::text_link` are now shared.
- **Shell.** `shell::unseen::Unseen` holds the dot: one Feed check per Shell, for the first known user (at start, or from `user_known`). Opening the Feed clears it and sends mark-seen from the Shell, not as a Page read, so leaving the Page doesn't abort it. A check that comes back after that is ignored. If the Feed is open when TIDAL first names the user, mark-seen is sent then. It is sent again on each Back/Forward to the Feed, as sone does on each mount. The sidebar has Explore (Compass) and Feed (Bell, with an accent dot), and they're marked when showing. The header avatar opens the user's own Profile, and a user playlist's creator name opens theirs.
- **Not done.** The avatar is still a placeholder: loading the user's picture (with `Profile.picture`) belongs with the user menu. Profile omits sone's external links and the clickable artist names in the bio (`strip_bio` makes them plain text). Profile editing is out of scope. The Feed Page has no play buttons or context menus (tickets 22, 25). Video cards on Explore lead nowhere (out of scope). A Feed opened before the user id is known shows the UnknownUser error, as the Library Pages do.
- **Tested:** Explore links and cards, view-all paths, dropped empty sections and links, Feed subtitles, targets, unreadable dates, month grouping (including across a new year and future months), the day-to-month arithmetic, the profile picture choice, the fan count formatting, bio markup, profile names, playlist cards, `Playlist::profile`, and the unseen dot. That's 249 tests in the workspace. **Run:** checked against TIDAL with the stored Session, through a throwaway probe: Explore (3 pill sections and 5 shortcuts), the genre, mood, decade, "New" and single-module pages, the Feed (42 entries, 18 unseen) and the own profile (no name, 1 public playlist). `pages/tidal_magazine` 404s at TIDAL, so it shows as not found. Other users' profiles couldn't be tried: search only finds editorial and artist playlists, whose creators aren't users. The app was started with a temporary patch that opened each new Page, and screenshots showed Explore, Genres, Pop, a View all grid, the Feed (dot gone once opened, back elsewhere) and the Profile drawing correctly. That run caught Explore itself being flattened into one list, and a blank link. Mark-seen was skipped in those runs, so the account's feed wasn't touched. I didn't click through the window by hand.
