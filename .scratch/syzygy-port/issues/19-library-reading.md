**What to build:** the user sees their Library: the sidebar lists their playlists, Folders, albums, artists and mixes with covers, the Library view-all Pages show each type (with Folders, which open to their playlists), and the Favorites Page shows their Loved tracks. Read-only in this ticket. See user stories 25, 49–50.

## Comments

Implemented. Notes for later tickets:

- **Catalog.** New `library` module. `Kind` (Playlists, Albums, Artists, Mixes), `LibrarySort { order: LibraryOrder, direction }` with sone's orders per type and its defaults (playlists `DATE_UPDATED DESC`, the rest `DATE DESC`). `LibrarySort::picked` is sone's `SortDropdown`: the same order flips, Name starts ascending, the rest start descending. `Shelf { user_id, kind, folder, sort }` is one list. Reads carry it, and a read for a shelf the user has left is dropped. `Catalog::library(&shelf)` reads the first page (UserContent tier, key `library:{user}:{Kind}:{folder|root}:{ORDER:DIR}`). Tags: `folders` + `fav-playlists` for playlists, `fav-albums` / `fav-artists` / `fav-mixes` for the others, and `user:{id}` on all of them. `more_library(&shelf, offset, cursor)` is uncached. Items are `Item::Folder | Item::Playlist | Item::Card`. Playlists and Folders come from `my-collection/playlists/folders`, paged by cursor. Mixes have more while pages come back full; albums and artists use TIDAL's total. `Catalog::loved_tracks(user, sort)` / `more_loved_tracks` read Loved tracks (key `fav-tracks:{user}:{sort}`, tags `fav-tracks` and `user:{id}`). With no sort they come last added first. `Paged` gained `cursor` and `total`. `Error::UnknownUser` is what a Library Page shows when it opens before TIDAL has said who the user is.
- **Settings.** `library_sorts` (Kind → sort), `loved_tracks_sort`, and one `Settings::save_sort(settings::Sort)` for every saved order (`Playlist`, `LovedTracks`, `Library`), written through `Action::SaveSort` → `app::Message::Sort`. Clearing them on a user switch is still ticket 32's job.
- **Routes.** `Route::Library { kind }`: the type is a tab, and switching it goes through `Action::Replace`. `Route::Folder { id, name }`: no tabs, in the playlists' order. `Route::Favorites` is the Favorites Page. `unbuilt.rs` is gone.
- **Sidebar** (`shell/sidebar.rs`). The pills pick a type, and each list is read the first time its pill is picked. Playlists are read when the Shell starts, so the cache fills the sidebar straight away. Loved Tracks is pinned above the playlists. A list stays on screen while it's read again in a new order, and is replaced when that read's first page arrives. Library Page sorts re-sort the sidebar through `Sidebar::sorted`. "Show all" opens the Library Page. The row for the Page on screen is marked. `Shell::user_known` (from `SessionInfo`) starts reads that were waiting for a user id. The sidebar has no sort control of its own: sone had one; here the order is picked on the Library Page. **Ticket 35:** the root playlists and Folders live in `Sidebar`, not in a `Library` state yet, and `List::apply` ignores a new first page once the list has paged. Both need to change when pending edits merge with `Fresh` reads.
- **Pages.** The Library Page is a grid of tiles (`cards::tile`, `cards::wrapped`), with Folder art and a sort picker shown as a row of orders. The count is TIDAL's total; for playlists that's the Folder's total, which includes Folders, as sone shows it. Favorites works like the Playlist Page: sortable header (no sort means last added first, and "#" goes back to it), filter, and a date added column. `track_list::matching` is now shared. New `page::loved_art` (sone's gradient heart) and `page::folder_art`, `hero::with_art`, `List::fail`/`cursor`/`total`, `style::loved`, `style::HL_MED`. New icons: heart, folder-open, arrow-up-down.
- **Message shape.** `app::Message::Navigate` was removed: it had become dead code. Sidebar links go `Shell(Sidebar(Link))` → `run_action`. Re-add it when the header search needs it.
- **Not done.** No filter on the Library Page (sone's needs the flattened playlists read). No context menus, hearts or play buttons (tickets 22, 25, 35+). No favorite videos (out of scope).
- **Tested:** Library sorts, orders and TIDAL params; Folder and playlist parsing with cursor paging; Folder and playlist subtitles; Favorite album, artist and mix cards and their paging; the Library and Loved tracks sorts in `Settings`. That's 196 tests in the workspace. **Run:** checked against TIDAL with the stored Session, through a throwaway test. Every type read (5 playlists, 5 albums, 50 + 9 artists paged, 2 mixes), albums sorted by name, Loved tracks in the default and title order, and cached rereads. The account has no Folders, so Folder parsing is only covered by the unit tests. The app starts, and the sidebar reads the playlists and their covers. I didn't click through the new Pages or watch them by eye.
