# 20: Search

**What to build:** the user types in the header and gets suggestions without leaving the Page they're on. Submitting a search or picking a suggestion opens a Search Page with tabs by type, and their last 10 searches are remembered. See user stories 42–44.

**Blocked by:** 17

**Status:** ready-for-agent

- [x] Suggestions are debounced 300 ms and shown in a Shell-owned dropdown under the header search
- [x] Submitting, or picking a suggestion, pushes `Search { query, tab }`. Switching tabs replaces the Back stack entry
- [x] A 10-entry search history is kept in `Settings` and offered in the dropdown

## Comments

Implemented. Notes for later tickets:

- **Catalog.** New `search` module. `Catalog::search(query)` reads up to 50 of each type (`TidalClient::search`, v2 then v1) into `SearchResults { top_hits, tracks, playlists, albums, artists }`. Videos are left out. It is not cached: sone kept search for 2 minutes in its frontend memory cache only, and the spec rules out a second in-memory cache. `Catalog::suggestions(query)` reads TIDAL's `/suggestions/` (10 queries) into `Suggestions { queries, hits }`. `Suggestion::searched_before` marks TIDAL's own record of the user's searches. A failed read is just no suggestions. A `Hit` is a `Track` or a `Card`. Card hits carry the subtitle as the dropdown writes it ("Artist", "Album · Björk", "Playlist · 12 Tracks"). `library::album_card` and `library::artist_picture` are now shared.
- **Header search** (`shell/search.rs`). This is the Shell-owned field and dropdown. Each keystroke returns `Effect::Wait(n)`. Only the wait after the last keystroke fetches, and suggestions that come back for an older query are dropped. A new fetch aborts the one before it. With nothing typed, the dropdown lists the past searches, with a way to forget each. Otherwise it shows the suggested queries, then the hits, then "View all results". Picking a hit opens it, and a track hit opens its album until there's playback (ticket 22: sone plays it alone). A click outside closes the dropdown, as does Escape. Clicks are global `Pressed` events, read against which part the pointer is over (`Enter`/`Leave` per `Zone`), because iced's text field has no blur event. Clear empties the field and puts the cursor back in it. Opening a Search Page puts its query in the field. Clicking the field then asks for suggestions if none were read for that query.
- **Search Page** (`page/search.rs`). `Route::Search { query, tab }` has tabs All Results, Top Hits, Tracks, Playlists, Albums and Artists. Switching tabs goes through `Action::Replace(route, None)`: `Replace` now takes an optional read, so a tab switch doesn't search again. All Results shows 8 tracks and 6 of each card type, each section with "View all" to its tab. Tracks is a windowed list with covers and albums. `page::search::hit` is the hit row that both the dropdown and Top Hits use. `style::list_row` is new, and so is the Clock icon.
- **Settings.** `search_history` holds the last 10 searches, newest first, each kept once whatever its case. `remember_search` and `forget_search` go through `app::Message::Searched` / `ForgetSearch`. Submitting, picking a suggested or past query, and "View all results" remember the search. Picking a hit doesn't, as in sone. **Ticket 32:** sone clears the search history on logout.
- **Not done.** Play buttons, context menus and hearts on results wait for tickets 22, 25 and 35. A track hit with no full track entity has no artists and `explicit: false`; ticket 26 should treat that as unknown. Ctrl+K to focus search isn't asked for here. The dropdown is lined up with the field from the header's constants (`HEADER_PADDING`, `STEP_SIZE`, `HEADER_SPACING`).
- **Tested:** results by type, top hits in TIDAL's order without videos, track hits as whole tracks, the suggestions' searched-before flag, the history (order, dedup ignoring case, cap, blanks, forgetting, saving), and the header search state: debounce, stale replies, the loading / none / suggestions / past searches states, submit, pick, clear, click outside, Escape, and reopening after a pick or Back. That's 223 tests in the workspace. **Run:** checked against TIDAL with the stored Session, through a throwaway test: suggestions for "bjork" (4 queries, one searched before, 15 hits), a search (99 top hits, 50 of each type), and an empty search. The app was started with a temporary patch that opened a Search Page with the dropdown showing, and both rendered as expected in a screenshot. That run caught a bug: covers coming into view closed the dropdown. I couldn't type into or click the window, so the debounce, closing and tab switching haven't been tried by hand.
