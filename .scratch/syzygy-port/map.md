# Map: Port sone to syzygy (pure-Rust iced)

Label: wayfinder:map

## Destination

A porting spec for the **syzygy** prototype, plus ordered implementation tickets ready to hand off. syzygy is a pure-Rust iced app that replaces sone's webview UI. It reuses sone's Rust code (refactored where iced needs it), in a workspace with one crate per backend subsystem plus one iced binary crate.

## Notes

- **Architecture:** follow the iced architecture (https://book.iced.rs/architecture.html). Logic that lives in sone's TypeScript (queue, shuffle, repeat, autoplay, history, session restore) is ported into the app's `update` and state, not into a separate core crate.
- **Reuse:** copy only the Rust modules the prototype needs. `sone/` (upstream at `0488f97`) is a gitignored, read-only reference. This is a new project, not a fork, so no upstream sync is needed.
- **Identity:** a separate app called syzygy. Crates are named `syzygy-*` and it has its own config dir and app ID. License GPL-3.0, crediting sone (lullabyX).
- **UI:** match sone's layout, but not pixel for pixel. One hardcoded dark theme matching sone's default.
- **Tests:** ported Rust tests come along with their modules. Queue, shuffle and repeat get tests at the `update` level. No tests for views.
- **Prototype scope:** login by device code and by PKCE through the system browser, with a persisted session. Browse: home, search, album, artist (plus all top tracks and view-all), playlist, mix, favorites, library, explore (plus explore sub-pages), feed (with mark-seen and an unseen badge), and profile (read-only) with its playlists. Library editing: favorites, playlists, folders. Playback through sone's audio engine, including bit-perfect output, with the queue, shuffle and repeat. Player bar and the now-playing drawer with lyrics. Settings: quality, output, bit-perfect, logout. MPRIS. tidal_report (reporting plays to TIDAL so they show in "Recently Played").
- **Skills:** call `grilling` and `domain-modeling` on grilling tickets. Call `codebase-design` for the crate-boundary work.

## Decisions so far

<!-- one line per closed ticket: [title](issues/NN-slug.md): gist -->

- [iced capabilities survey](issues/01-iced-capabilities-survey.md): target iced 0.14.0 with features `tokio,image,svg,lazy,advanced`. iced owns the tokio runtime. Backend channels are bridged through a `stream::channel` worker. Cover-art cache is ours to build. No virtualized list upstream, so long track lists need hand-rolled windowing. Context menus come from `iced_aw` 0.14.1.
- [Backend dependency and Tauri coupling inventory](issues/02-backend-dependency-inventory.md): the core (tidal_api, cache, crypto, rate_gate, proxy, pipeline_probe) is already Tauri-free, apart from crate-root types in `lib.rs`. Only audio, signal_path and mpris hold an `AppHandle`, and they use it to send events. Proxy is wired into `TidalClient` and `AudioPlayer`. Out-of-scope services (discord, scrobble, mcp) are called from playback and auth paths. PKCE through the system browser works by pasting the redirect URL back.
- [Frontend behavior inventory](issues/03-frontend-behavior-inventory.md): about 20 playback atoms. The manual queue plays before the context queue, and entries are keyed by qid. `playNext` and `playPrevious` follow detailed precedence rules (repeat-one, then the source stash, then skipping unplayable tracks, then rebuilding for repeat-all, then autoplay radio). Gapless prefetch arms only the next head from the same source. Session restore always comes back paused. Library edits are optimistic with rollback, using TRNs. Lists the commands per screen and 30 candidate glossary terms.
- [Workspace crate boundaries](issues/04-workspace-crate-boundaries.md): a virtual workspace with `syzygy-{tidal,store,audio,mpris,catalog,report}` plus the `syzygy` binary. No core crate, and each crate has its own error type. Proxy is stripped (ADR 0001). The `syzygy-catalog` crate owns stale-while-revalidate caching and is the binary's only way to reach Catalog content. Stream resolution and auth helpers move from the commands layer into `syzygy-tidal`. Audio and mpris emit typed event enums. `AppState` isn't ported, and out-of-scope service calls disappear with the commands layer. Dependencies are bumped to current stable.
- [Backend-to-iced bridge](issues/05-backend-iced-bridge.md): a `Services` struct of `Clone` handles is built in `boot` and stored in `App`. `TidalClient` takes `&self` and refreshes tokens single-flight. The audio API is async (oneshot replies) and runs as `Task`s. Engine events come from receivers created in `boot`, through `run_with` subscriptions (ADR 0003). Playback logic is pure and returns `Effect`s (ADR 0002). Catalog reads are `Cached`-then-`Fresh` streams. `update` is the only writer of settings, and tidal emits `TokensRefreshed` and `SessionExpired`. Position comes from a lock-free `PositionCell` shared with MPRIS. The reporter runs its own flush loop. Messages carry `Arc` errors. Quit runs a shutdown task before `iced::exit()`.
- [Auth flow in iced](issues/06-auth-flow-in-iced.md): Browser login (PKCE) is the default, and device-code login is a secondary link marked "no lossless". Only embedded client IDs are used. Browser login finishes when the user pastes the redirect URL or code (or uses a clipboard button), because the redirect URI is fixed. The Session (tokens, `AuthMethod`, `user_id`, `country_code`) lives in its own encrypted `session.json` under keyring `syzygy`/`master-key`, and a crypto failure is fatal. Startup goes straight to the shell and refreshes session info in the background. Tokens refresh only after a 401. Only `invalid_grant` counts as Session expiry, and expiry keeps the queue and cache unless a different user signs in. Logout wipes the session, cache and queues but keeps preferences.
- [App state, messages and navigation](issues/07-app-state-messages-navigation.md): `App { services, settings, playback, images, phase: Fatal|Login|Shell }`, so playback outlives the Shell. Each Page is a module whose `update` returns an `Action`, and there are 15 Pages. The Back stack supports back and forward, and each entry is a `Route` plus a scroll offset (cap 50). Tabs are part of the route and switching them replaces the entry. Settings is a modal. Messages are stamped with a `PageId`, and a Page's loads are cancelled when it's dropped. Page data is held as `Remote<T>` and read through catalog SWR, with no second in-memory cache. Queue-filling loads belong to playback. Drawer tabs load lazily for the current track. Cover art comes from an image LRU at the `App` level.
- [Playback and queue model](issues/08-playback-queue-model.md): the Playback source owns its tracks, and playback keeps a play order plus a cursor (ADR 0004). The Manual queue is separate, with Source tags, so `originalQueue` and the context-source stash go away. No wrap-around, and every play has a source, including single tracks. Card play respects Shuffle. Autoplay makes the Track radio the source and stops when there is none. Allow-explicit is in scope, with a consent modal owned by the Shell, and explicit tracks are skipped silently during an advance. The continuation is plain data saved in the snapshot, run through `StartFill`/`CancelFill`. Play tokens replace the locks, and the skip drain is a state machine. Gapless arms any next step already known in state. Preferences live in `Settings`, and `queue.json` restores paused at the saved position.
- [Visual system prototype](issues/09-visual-system-prototype.md): layout A (faithful sone) wins, with a 280px sidebar, 64px header, hero, 60px rows with covers, a 90px player bar, and a slide-up drawer split 45/55. Styling uses `const` tokens from sone's Violet Night plus one style fn per widget over `Theme::custom`, with no custom Theme type. Track lists must be windowed (fixed row height plus spacers). Covers load through `sensor`, then decode off-thread, then `image::allocate`, then fade in, held in an LRU. Icons are sone's Lucide set, as SVGs through iced's `svg` widget. Still needed: a max content width on wide windows. The prototype lives on branch `prototype/visual-system`.
- [Library editing interactions](issues/10-library-editing.md): one `Vec<PendingEdit>` plus a single `library::apply` merge replaces sone's overlay maps. Rollback means dropping the edit, edits are serialized per target, and `library::update`/`apply` form test Seam 3. Sorting stays server-side. Removing a track from a sorted view resolves its own-order index with a fresh read, matching on (track id, dateAdded). Adding a selection skips duplicates and reports how many. Folders are one level deep and only empty ones can be deleted. Recents and sorts are in `Settings`, cleared on user switch. A deleted Playback source keeps playing and cancels its fill. Pages open dialogs through `Action::Library`.

- [Porting spec](spec.md), accepted as written for these items (not grilled):
  - **Settings modal:** max quality, exclusive mode with device list, bit-perfect, gapless, volume normalization, Autoplay, allow explicit, report plays, Logout.
  - **Lyrics:** from TIDAL's track lyrics endpoint via `syzygy-catalog`. LRC `subtitles` give a synced view that highlights and auto-scrolls (paused on user scroll, "Sync lyrics" resumes). Otherwise plain text, otherwise "No lyrics available". Right-to-left lyrics align right.
  - **Errors and logging:** toasts are Shell state with auto-dismiss, Page failures are inline with Retry, `Phase::Fatal` only for crypto and keyring failures. Logs go to a file, with the level set by an env var.
  - **Identity:** app ID `com.lorenzorapetti.syzygy`, config and cache dirs `<config_dir>/syzygy` and `<cache_dir>/syzygy`, MPRIS bus name `org.mpris.MediaPlayer2.syzygy` with identity `Syzygy`.

- MCP server, overlay server, Discord, scrobbling, tray, global shortcuts.
- Proxy support and `webview_proxy_auth`.
- Theme presets and custom `theme.json`, session import, the PKCE webview login window.
- Update check, idle-inhibit, the signal-path panel, deep links, single-instance.
- Profile editing (name, handle, bio, links, picture). Profile is read-only (07).
